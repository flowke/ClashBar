# ClashBar 需求记录

按编号追加需求，保留用户确认的决策和验收条件。收到实现指令后，按编号逐项实现已确认的需求，并在对应条目记录验收结果。

## CB-001 配置页默认进入「自定义配置」

- **记录日期** 2026-11-23
- **需求** 从仪表盘侧栏进入「配置」时，默认选中「自定义配置」。用户仍可手动切换到另外两个标签。
- **已确认** 每次从侧栏进入「配置」都选中「自定义配置」，包括从其他页面切回时。用户可手动切换标签。关闭仪表盘窗口后重新打开，如果直接回到原配置页，则保留关窗前选中的标签。
- **验收** 首次进入「配置」时选中「自定义配置」。切到「生效的配置」，前往「概览」再返回「配置」，应重新选中「自定义配置」。再切到「生效的配置」，关闭并重开仪表盘窗口，直接回到配置页时应保留「生效的配置」。
- **实现记录** 配置页使用「自定义配置」作为初始标签，仪表盘重开时复用原窗口。窗口复用和配置页渲染测试通过。

## CB-002 压缩「已添加规则」的条目高度

- **记录日期** 2026-11-23
- **需求** 降低「自定义配置 → 已添加规则」中每条规则占用的高度，同屏显示更多规则。用户提出可用表格或分列布局。
- **已确认 · 表格** 每条规则占一行，按优先级从上到下显示。列为「类型（新增／替换／删除）｜规则摘要｜启用｜测试状态｜操作」。保留启用开关及测试、编辑、删除或撤销删除等现有操作。
- **已确认 · 详情** 点击详情查看原始规则、测试地址及完整测试结果，包括命中规则、线路和错误信息。表格内显示简要测试状态，测试结果更新时保持行高稳定。
- **已确认 · 滚动** 压低每行高度，沿用配置页整体滚动。
- **验收** 用截图中的 5 条规则，在相同窗口尺寸下确认列表比原卡片布局更矮。检查列标题、优先顺序与现有操作。验证测试前、排队、测试中及完成后行高稳定，详情可查看完整信息。在最窄窗口宽度下检查长规则与详情入口，在规则较多时确认可通过整页滚动访问所有条目。
- **实现记录** 规则表格使用 36 pt 行高，操作图标提供文字提示，详情使用浮层。规则测试与配置页渲染测试通过，已检查常规和最窄窗口的渲染截图。

## CB-003 服务状态改为单行显示

- **记录日期** 2026-11-23
- **需求** 「服务状态」表格中的每项服务只占一行，检测状态更新时行高保持稳定。
- **已确认 · 表格** 保留「服务｜当前线路｜直连对照｜操作」四列。服务列显示图标和名称。两种线路都显示文字状态和耗时，耗时右对齐。当前线路有可确认的实际节点时，额外显示末级节点摘要。名称和节点过长时单行截断。
- **已确认 · 详情** 在操作列提供「详情」，点开浮层查看完整测试地址、两种线路的完整结果、实际策略链、HTTP 状态、命中规则和错误原因。内置服务显示锁定标记，在「服务状态」手动添加的服务保留删除入口。从配置同步的服务按 CB-004 管理。
- **验收** 用截图中的 7 项服务，在相同窗口尺寸下确认表格更矮。检查长名称和节点不会换行，可达、访问受限、已取消及待重新检测状态能直接区分，且两条线路的耗时便于比较。最窄窗口下也能访问详情及行内操作。
- **实现记录** 服务行从 88 pt 缩至 36 pt，完整地址和检测结果移入详情浮层。服务状态渲染测试通过，并检查了 760 pt 窗口宽度下的状态文字、耗时和操作入口。

## CB-004 将规则的测试地址同步到服务状态

- **记录日期** 2026-11-23
- **已确认 · 新增与补填** 在「配置 → 自定义配置」新增规则时，保存了有效的测试地址就自动同步到「服务状态」。新增时留空、之后编辑补填测试地址的规则，也在保存成功后自动出现在「服务状态」。
- **已确认 · 删除权限** 同步条目归源规则管理，「服务状态」不提供删除入口。在配置页删除源规则后，自动移除对应的同步条目。
- **暂定** 以源规则保存的测试地址为准。停用规则后仍保留带地址的同步条目。更换地址时更新对应服务，并将其标为待检测。在配置页清空地址并保存后，移除对应的同步条目，保留源规则。
- **验收** 分别验证新增时填写测试地址、先留空再编辑补填、从服务状态无法删除同步条目，以及从配置页删除规则后自动移除对应服务。补填后应在保存成功时自动显示。
- **实现记录** 已按上述行为实现。同步条目按规则 ID 识别，手动添加的同址服务独立保留。已通过新增、编辑补填、保存失败、重新加载、停用、更换或清空地址及删除源规则的回归验证。

## CB-005 调整网址输入框的占位文字和默认前缀

- **记录日期** 2026-11-23
- **需求** 「配置 → 自定义配置 → 新增规则」的「测试地址（可选）」和「服务状态 → 新增」的「检测网址」都使用较浅且清晰可读的灰色占位文字。打开新增表单时，输入框默认预填可编辑的 `https://`，可直接在后面输入域名，也可改用 `http://` 或粘贴完整地址。
- **保存行为** 可选的规则测试地址留空或仅保留 `https://` 时，按未填写处理，仍可保存规则，且不会触发 CB-004 的同步。服务状态的新增表单要求填写有效的完整 HTTP 或 HTTPS 地址后才能添加。
- **验收** 打开两个新增表单，检查默认值为 `https://`。清空输入框后，示例地址以浅灰色显示。验证可补写域名或替换为完整地址，并分别检查只保留前缀时能保存规则，以及服务新增按钮仍不可用。
- **实现记录** 两个表单共用系统灰色占位文字和可编辑的 HTTPS 前缀，编辑已有规则时保留已保存的地址。已通过前缀、清空及粘贴完整网址的回归测试，服务新增表单的渲染截图显示仅有前缀时添加按钮不可用。

## CB-006 配置规则展示实际线路与测试色点

- **需求** 「已添加规则」新增「线路」列，显示测试观测到的末级节点。尚无观测结果时显示 `—`，完整线路可从悬停提示和详情查看。
- **需求** 测试状态在表格内用色点表示。命中为绿色，未命中为橙色，请求失败为红色，无法确认为紫色。排队和测试中用深浅蓝色区分，其余状态用灰色。悬停、辅助功能和详情保留文字说明。
- **验收** 分别测试直连和代理规则，检查线路列及完整线路，并检查不同测试结果的色点和悬停说明。

## CB-007 服务名称优先分配表格宽度

- **需求** 「服务状态」为当前线路和直连对照保留紧凑列宽，剩余宽度优先给服务名称。长名称在空间不足时单行截断，仍可悬停或打开详情查看全文。
- **验收** 在常规宽度下检查 `download.open-design.ai` 等长名称，在窄窗口下检查线路状态、耗时与详情入口。

## CB-008 规则列表显示配置目标线路

- **记录日期** 2026-11-26
- **需求** 「已添加规则」需要直接显示规则配置的目标线路，让用户能一眼判断匹配的域名会走 `DIRECT` 直连，还是交给指定的代理线路／策略。域名摘要回答“匹配什么”，目标线路回答“流量交给谁”，两者都是理解规则意图的关键信息。
- **现状** 当前「线路」列依赖测试结果显示实际观测到的末级节点；测试前显示 `—`。这表示测试观测，不一定能说明规则配置指定的目标策略。
- **待对齐** 目标线路显示策略组／策略名称、实际节点，还是两者；如何表示规则组、回退策略及目标不可用等情况；测试观测到的实际线路继续放在表格还是详情中。
- **讨论目标** 表格无需先运行测试或打开详情，就能看清规则是直连还是指定代理去向；配置目标与测试观测结果应能明确区分。

## CB-009 可视化查看并管理规则分组

- **记录日期** 2026-11-26
- **需求** 在配置中提供一个可视化入口，查看当前配置已有的分组和规则，并可直接新建分组、挑选已有规则加入分组。截图以「配置 → 选择的配置」中标记为当前基础配置的订阅卡片为上下文；具体入口位置待确认。
- **已确认 · 分组语义** 这是实际线路分组／策略组，不只是用于整理规则的界面分类。用户选择的规则统一走该分组指定的线路。
- **已确认 · 适用配置** 不限于截图圈出的当前基础配置卡片，其他配置也可以创建和管理这类分组。
- **已确认 · 更新后保留与检查** 配置更新后，新建的分组及其规则关联仍要保留。更新后检查分组引用的线路；如果线路在新配置中缺失，在分组卡片上显示明显警告，让用户能发现异常。
- **待对齐 · 策略组结构** 一个分组可以包含多条线路吗？如果可以，如何选择或切换组内线路（手动选择、自动测速、故障回退等）；这会决定分组本身的路由行为。
- **待对齐 · 规则范围与配置作用域** 可选内容包括基础配置中的逐条规则、规则集／规则提供者，还是也包括 ClashBar 自定义新增、替换和删除的规则？分组是每个配置独立保存，还是多个配置共享？
- **待对齐 · 持久化方式** 需要在订阅更新后保留分组和规则关联；具体通过本地覆盖、订阅差异合并或其他方式实现，仍待确定。
- **待对齐 · 缺失线路处理** 警告要展示哪些缺失线路、是否提供替换线路入口，以及线路缺失期间相关规则如何处理。
- **待对齐 · 操作与顺序** 是否需要重命名、排序、删除分组，以及将规则移入／移出分组？规则优先级顺序会影响匹配结果，需要确定分组操作如何保持或调整规则顺序。
- **讨论目标** 用户能可视化理解配置规则和实际线路分组，在订阅更新后保留自建分组并及时发现线路缺失；其余路由、编辑和恢复细节对齐后再统一设计与开发。
